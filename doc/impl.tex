\chapter{About This Guide}

This guide describes the \textbf{Quarb engine}: the Rust
implementation of the Quarb query language, its \texttt{qua}
command-line tool, and the adapter architecture that lets one engine
query many data sources. The language itself\,---\,its data model,
execution model, and syntax\,---\,is defined in the \emph{Quarb
Language Specification} (the \texttt{lang} sibling project); this
guide covers only the implementation.

\paragraph{The guide tracks the code.}
The engine is being built as a series of thin, working slices rather
than from a finished design. This document tracks that process:
constructs the engine \emph{already implements} are marked \live and
documented against the real code; constructs that are specified but
\emph{not yet built} are marked \planned and sketch the intended
surface. As each slice lands, its \planned entries become \live. The
current milestone is a \emph{walking skeleton}: rooted tree
navigation over a filesystem.

\paragraph{Central concern: the adapter surface.}
The one design question this guide most needs to get right is the
\emph{adapter surface}\,---\,the trait a data source implements to be
queried. That surface is deliberately being grown against a concrete
first adapter (the filesystem) so that its shape is driven by real
navigation problems rather than speculation. Chapter~\ref{ch:adapter}
is its home.


\chapter{Architecture}

The engine follows a conventional compiler-style pipeline. A query
string is lexed and parsed into a small AST, which the executor
evaluates by driving an \emph{adapter} over the target data:

\begin{lstlisting}
[query string]
      |  lexer          quarb::lexer
      v
[tokens]
      |  parser         quarb::parser
      v
[query AST]             quarb::ast
      |  executor       quarb::exec
      v
[node set]  <-- drives --  [AstAdapter]  --> [data source]
\end{lstlisting}

\noindent
The executor never touches the data source directly. It knows only
the \texttt{AstAdapter} trait (Chapter~\ref{ch:adapter}), so the same
query runs unchanged over any adapter.

\texttt{quarb-relational} & The shared relational model: tables
  as root children, rows named by primary key, columns as
  properties, declared foreign keys driving
  \texttt{-->} resolution (chained hops instead of
  JOINs), \texttt{->}/\texttt{<-} crosslinks labeled by column,
  \texttt{<--(::fk)} reverse resolution from the declared keys
  (\texttt{reverse\_resolve} on the relational model), and the
  table-naming reference label for undeclared references (required
  where a column declares no key). Loading is catalog-
  eager, rows-lazy, hops by key: a table is read whole only when a
  query lists it (\texttt{/t/*}, \texttt{:::n-rows}); a hop reads
  the rows it lands on through the driver's keyed source
  (\texttt{WHERE key IN (\dots)}, one statement per frontier; such
  a row carries no row id until the table is read, never a
  sentinel value a real row could bear), rows
  keep their identity when the table is later read whole, and
  untouched tables are never read (\texttt{:::loaded},
  \texttt{:::n-loaded} report the state). Engine
  adapters are thin catalog drivers over it. Depends on
  \texttt{quarb}. \\
\texttt{quarb-sqlite} & The SQLite catalog driver: PRAGMA

  \texttt{quarb-relational} and \texttt{rusqlite}. \\
\texttt{quarb-objstore} & GCS and S3 buckets as lazy

  Composed by default in \texttt{qua}: a bucket of JSON / CSV /

  crosses from cloud storage into the document mid-path —
  grafting is this adapter's point. GCS: anonymous for public
  buckets, gcloud-token auth otherwise. S3: anonymous only in
  v1 (SigV4 signing is a recorded extension — private buckets
  refuse). \\
\texttt{quarb-postgres} & The PostgreSQL catalog driver:

  Depends on \texttt{quarb-relational}. \\
\texttt{quarb-mysql} & The MySQL/MariaDB catalog driver:
  \texttt{information\_schema} introspection over \texttt{sqlx}

  else \texttt{CAST(... AS CHAR)} into the numeric-reading

\texttt{quarb-mssql} & The SQL Server catalog driver:
  \texttt{INFORMATION\_SCHEMA} plus \texttt{sys.foreign\_key\_columns}

  \texttt{tiberius} (pure-Rust TDS, internal current-thread
  runtime); \texttt{bit}/integer/float/character families
  native, everything else \texttt{CAST(... AS NVARCHAR(MAX))}.
  Target: \texttt{mssql://USER:PASS@HOST[:PORT]/DATABASE}.
  Depends on \texttt{quarb-relational}. \\
\texttt{quarb-oracle} & The Oracle catalog driver: the
  \texttt{USER\_*} dictionary views over the \texttt{oracle}
  crate (ODPI-C, synchronous); \texttt{NUMBER(p,0)} integer,

  everything else \texttt{TO\_CHAR}. Target:
  \texttt{oracle://USER:PASS@HOST[:PORT]/SERVICE}. Depends on

\texttt{quarb-ldap} & The LDAP directory driver: the DIT
  \emph{is} the arbor — the base DN is the root, an entry's
  children are the entries one level below (RDN names), its
  attributes are properties (multi-valued as lists),

  \texttt{ldap[s]://[USER:PASS@]HOST[:PORT]/BASE\_DN}. \\
\texttt{quarb-cbor} & The CBOR (RFC~8949) adapter, the JSON

\texttt{quarb-csv} & The CSV/TSV adapter (one \texttt{row} node per

  REST API directly (\texttt{jobs.query} over a synchronous HTTP
  client — no cloud SDK, no async runtime), bearer token from
  \texttt{QUARB\_BQ\_TOKEN} or \texttt{gcloud auth
  print-access-token}, catalog from
  \texttt{INFORMATION\_SCHEMA} including the \emph{unenforced}
  key constraints (declare them and the reference machinery
  works). The execution ladder is a billing instrument here:
  BigQuery meters bytes scanned, so lazy loading, pushdown, and
  \texttt{--save} directly reduce cost. Target syntax:
  \texttt{bigquery://PROJECT/DATASET[?account=EMAIL]}. \\
\texttt{quarb-duckdb} & DuckDB, the fifth catalog driver —
  and the columnar side door: a \texttt{CREATE VIEW ... AS
  SELECT * FROM read\_parquet(...)} makes Parquet first-class.
  Keys from \texttt{duckdb\_constraints()} (the
  \texttt{information\_schema} FK view reports the referencing
  side only), rows lazy, \texttt{raw\_query} for the ladder,
  read-only connection. Bundled build; \texttt{.duckdb} /
  \texttt{.ddb} by extension. \\
\texttt{quarb-xlsx} & Spreadsheets (\texttt{.xlsx} /
  \texttt{.xls} / \texttt{.ods}, via calamine) on the
  relational model: sheets as tables, first-row headers as
  columns (positional \texttt{cN} for blank/duplicate), rows
  named by sheet row number, numeric cells typed. No keys —
  sheets declare none — so resolution needs hints. Dispatched by
  extension \emph{before} the archive check (workbooks are
  zips; the sheets are the point). \\
\texttt{quarb-firebase} & The Firebase Realtime Database
  driver: the RTDB \emph{is} a JSON tree, so the mapping is
  \texttt{quarb-json}'s, fetched lazily one node per shallow
  GET and cached. Properties are direct fetches
  (\texttt{::score} is one tiny request); \texttt{\textasciitilde>}
  resolves by hint naming a root-relative container
  (\texttt{::parent\textasciitilde>item}). Containers that
  refuse enumeration (permission-scoped or unbounded — the
  public Hacker News database's \texttt{/v0/item} holds tens of
  millions of keys) are \emph{opaque}: reachable by name, empty
  to wildcards — served by the engine's new
  \texttt{children\_named} fast path. References are \emph{declared
  client-side}: a refs document
  (\texttt{\{"refs": \{"parent": "item", "kids/*": "item"\}\}},
  supplied via \texttt{qua --refs}) is the portable mini-catalog
  a schemaless substrate cannot hold — with it, bare
  \texttt{\textasciitilde>} resolves and \texttt{->} crosslinks
  enumerate (array fields one probed edge per element); an inline
  hint overrides. Reverse resolution stays empty (it would scan
  what opaque containers refuse; server-side \texttt{.indexOn}
  queries are the recorded v2 path). Target:
  \texttt{firebase://HOST/PATH[?auth=...]}. Read-only. \\
\texttt{quarb-tree-sitter} & Source code as its literal syntax
  tree — the syntax level (né \texttt{quarb-code}): node kinds
  as edge names (\texttt{//function\_item}), tree-sitter
  \emph{fields} as properties (\texttt{::name} on a function is
  its name), source text as the value, \texttt{:::start-line} /
  \texttt{:::kind} / \texttt{:::field} metadata; named nodes
  only. Rust / Python / JavaScript / C by extension,
  compile-time grammar set. Grafts under composition —
  \texttt{--graft} queries every function in a directory tree
  at once. \\
\texttt{quarb-code} & Source code at the code level:
  declaration identifiers are node names
  (\texttt{/lexer/lex}), anonymous constructs keep a
  normalized cross-language vocabulary (\texttt{if},
  \texttt{switch}, \texttt{for}, \texttt{call}), everything
  else dissolves (children hoist). Curated traits
  (\texttt{<function>}, \texttt{<type>}, \texttt{<loop>});
  \texttt{::signature} / \texttt{::doc} / \texttt{::callee};
  raw backend kind only at \texttt{:::kind} (aliased, closed
  surface); \texttt{->definition} file-local crosslinks, one
  declaration list per identifier: a qualified callee
  (\texttt{Type::new}, \texttt{obj.helper}) prefers the
  declarations under that qualifier, an unqualified one fans out.
  Opt-in via the \texttt{code:} target prefix;
  \texttt{code:DIR} grafts every supported source leaf —
  filesystem into declarations, one namespace. \\
\texttt{quarb-compose} & Adapter \emph{composition}: wrap any
  adapter and a leaf whose name or content parses (json / xml /
  html / csv, else a sniff) grafts its parsed arbor as children —
  \texttt{/data/store.json/books/*} crosses from filesystem into
  JSON mid-path. Marked-up members graft at the DOM by default or,
  under \texttt{DocumentGraft::Text} (\texttt{text:} on an
  archive), as the text level; the source-level grafts
  (tree-sitter, the code model) sit behind the default
  \texttt{source} feature so the wasm build can leave them out.
  Grafts are lazy (read + parse on first entry),
  the inner root is identified with the outer leaf (no phantom
  node), and locators mark the boundary jar-style
  (\texttt{store.json!/books/1}). \texttt{qua}: default for
  archives, \texttt{--graft} for directories. \\
\texttt{quarb-archive} & Zip, tar and 7z archives as directory trees
  (entries as nodes, content as value, \texttt{:::size} /
  \texttt{:::compressed}), every format through a pure-Rust
  library so the wasm build reads them too: zip members deflate,
  deflate64, bzip2 (\texttt{bzip2} with \texttt{libbz2-rs-sys}),
  lzma (\texttt{lzma-rs}); tar plain and under gzip
  (\texttt{flate2}), xz (\texttt{lzma-rs}), bzip2, zstd
  (\texttt{ruzstd}); 7z (\texttt{sevenz-rust}, LZMA/LZMA2). The
  format is told by its magic bytes. Zip members in zstd or xz and
  rar would need a C library and are not read by default:
  rar rides the opt-in \texttt{rar} feature over the
  \texttt{unrar} crate (rarlab's library under its own licence),
  on for \texttt{qua}, off for the playground and the extension,
  and a RAR without it is refused naming the feature. CHM help
  files read through \texttt{libchm} (pure Rust, \texttt{ITSF}):
  members under their paths, the system records left out, a page
  without a \texttt{<meta charset>} decoding under the
  \texttt{\#SYSTEM} locale's code page. An MHTML web archive
  (\texttt{.mhtml}, \texttt{.mht}, or MIME header lines) reads
  through an in-crate RFC 2045/2046 splitter: each part a member
  under its \texttt{Content-Location} path, transfer-decoded,
  its charset the declaration. Members decode under the mount's
  source-boundary rule. \\
\texttt{quarb-web} & The \emph{web level}: a site as an arbor —
  \texttt{/sites/<host>/pages/<path>} for every page (directories
  from the URL paths, \texttt{<dir>} / \texttt{<page>} /
  \texttt{<redirect>}), the declared categories and tags as rows
  of their own containers, every hyperlink of the DOM resolved
  into \texttt{->link} / \texttt{<-link} (\texttt{->category},
  \texttt{->tag}, \texttt{<-page}, \texttt{<-category}), the
  degrees, \texttt{::pagerank}, \texttt{::redlinks}, and
  \texttt{<orphan>} as columns; each page grafts at the text
  level on entry, and a prose \texttt{ref} that leaves its page
  resolves to the page it names. Rows answer to their kind
  (\texttt{//page}), their segment, its stem, their title. A
  \texttt{WebStore} contract behind it; stores: in-memory from a
  tarball (\texttt{archive}, the wasm \texttt{Site}) or a
  directory (\texttt{fs}), SQLite (\texttt{sqlite}), PostgreSQL
  (\texttt{postgres}; COPY export, deferred foreign keys), one
  schema in two dialects. A planner over the reflected query
  answers on three rungs — Full (a bare count, every conjunct
  exact), Prefilter (a superset of the enumerating step's
  matches; the engine re-runs the query over the level scoped to
  the candidates), Scan — with the text prefilter resting on
  \texttt{page\_text.plain} = the graft's own
  \texttt{plain\_text()}. The four adapter hooks
  (\texttt{document\_by\_ref}, \texttt{reverse\_resolve},
  \texttt{descendants\_named}, \texttt{prefetch\_links}) let a
  store answer where the engine would walk.
  \texttt{quarb-web-ingest} (\texttt{cli}): \texttt{crawl} a
  directory or archive into a store, \texttt{wikipedia} the
  Wikimedia Enterprise HTML dumps (streamed; links by URL then
  through redirects; \texttt{--tree=path|category}),
  \texttt{analyze}, \texttt{index} (pg\_trgm). \texttt{qua}:
  \texttt{web:<dir|archive|site.db|postgres://…>},
  \texttt{--explain} / \texttt{--no-pushdown}. \\
\texttt{quarb-trace} & The \texttt{quarb/trace} viz contract as
  Rust: the payload types (arbor snapshot, steps, threads,
  snapshots, window and stubs, positions, ribbons, lookahead
  verdicts, results) and their kaiv writer; no dependencies, no
  reader. \texttt{quarb::trace::trace} fills one by
  \emph{replaying} the query rather than instrumenting the
  evaluator: one hop per live thread through the evaluator's own
  \texttt{navigate\_paths} (candidates with the predicates
  stripped, survivors with them --- the fork, the verdicts, the
  walked edges), \texttt{apply\_command} per thread for filters and
  over the whole context for aggregates, a hand-iterated walk for
  quantified groups (one frame per depth), then checks the final
  context against a plain evaluation. A staged suffix marks the
  steps beyond the committed query (a filter preview); a window
  selects the slice of a large result list to embed and what the
  stubs on either side measure. \texttt{Doc::trace} in
  \texttt{quarb-session} is the entry; the renderers read the
  kaiv document (quarbopsis: \texttt{quao trace}). \\
\texttt{quarb-maildir} & Maildir (\texttt{cur/}+\texttt{new/})
  and mbox mailboxes: headers as properties (lowercased), the
  body as the value, \texttt{:::epoch} parsing the Date header
  for range predicates. The thread graph is reference fabric:
  \texttt{::in-reply-to\textasciitilde>} walks to the parent
  message, \texttt{<-in-reply-to} finds the replies, via a
  Message-ID index. Never touches flags; read-only. \\
\texttt{quarb-firestore} & Google Firestore (native mode):
  collections and documents alternate as the arbor's levels; map
  and array fields descend as children, subcollections beside
  them. \texttt{referenceValue} fields are \emph{native}
  references — the first remote adapter where
  \texttt{\textasciitilde>} and \texttt{->} need neither a
  schema nor a refs file. Lazy per level, REST direct, token via
  \texttt{QUARB\_GCP\_TOKEN} / gcloud. Target:
  \texttt{firestore://PROJECT/DATABASE[?account=...]}. \\
\texttt{quarb-datastore} & Google Cloud Datastore (Firestore in
  Datastore mode): kinds and entities, the most relational of the
  document stores; \texttt{keyValue} properties are native
  references (\texttt{\textasciitilde>}/\texttt{->} schema-free).
  Kind list via a \texttt{\_\_kind\_\_} query, entities via

  \texttt{datastore://PROJECT[/DATABASE][?account=...]}. Both
  drivers send the \texttt{x-goog-request-params} routing header
  named databases require. \\
\texttt{quarb-mongodb} & MongoDB: collections hold BSON
  documents, named by \texttt{\_id} (ObjectIds as hex); embedded
  documents and arrays descend as children. DBRef fields
  (\texttt{\{\$ref, \$id\}}) are native references
  (\texttt{\textasciitilde>}/\texttt{->} schema-free). BSON dates

  reference targets by single \texttt{findOne}s; official Rust

  \texttt{mongodb://HOST[:PORT]/DATABASE[?options]} (or

\texttt{quarb-kubernetes} & The Kubernetes API, which is
  already a tree: the root holds one listing per discovered
  resource (cluster-scoped kinds plus the all-namespaces view,
  kubectl's \texttt{-A}); each namespace object carries its
  scoped listings beside its own fields; objects descend as
  their JSON, RFC\,3339 strings as instants.
  \texttt{ownerReferences} are native references
  (\texttt{::owner\textasciitilde>} climbs Pod → ReplicaSet →
  Deployment schema-free; \texttt{->node},
  \texttt{::namespace\textasciitilde>}); unknown property names
  fall through to \texttt{metadata.labels}. Lazy per listing,
  discovery at connect. Transport is \texttt{kubectl get --raw}

  \texttt{QUARB\_KUBECTL} overrides the binary), so contexts and
  auth behave exactly as kubectl does. Read-only. Target:
  \texttt{k8s:} / \texttt{k8s:CONTEXT} (alias
  \texttt{kubernetes:}). \\
\texttt{quarb-gcplogs} & Google Cloud Logging as a bounded
  snapshot — never a tail: the target must carry
  \texttt{since=} (a gcloud freshness duration or an ISO
  instant) and/or \texttt{limit=}, and an unbounded mount is

  property, lowercased trait
  (\texttt{/entry<error>}), and ordered numeric rank
  (\texttt{:::severity}, GCP's enum values); timestamps as
  typed instants; \texttt{::trace} the bare trace id — the
  \texttt{<=>} join key across services. Unknown property
  names fall through payload top level → labels → resource
  labels → httpRequest. \texttt{filter=} passes a raw Cloud
  Logging filter to the server (the mount-side cut);
  \texttt{until=} joins it as a timestamp clause. Transport is
  \texttt{gcloud logging read --format=json} over subprocess
  (kubectl posture; \texttt{QUARB\_GCLOUD} overrides —
  the bottled test fixture's hook; \texttt{account=} picks the
  gcloud account). Read-only. Target:
  \texttt{gcl:PROJECT?since=1h\&filter=…\&limit=N} (alias
  \texttt{gcplogs:}). \\
\texttt{quarb-cwlogs} & AWS CloudWatch Logs, the gcplogs
  design sheet over SigV4 (shared \texttt{quarb-aws} signing,
  credential chain, region resolution): bounded snapshots

  Target: \texttt{cwl:[GROUP]?since=1h\&filter=…\&limit=N}

\texttt{quarb-azlogs} & Azure Monitor Logs through the Log
  Analytics KQL endpoint — the adapter composes the KQL itself
  (bounded table scan, \texttt{filter=} as a \texttt{| where}
  clause, \texttt{take} from \texttt{limit=}); \texttt{table=}
  and a bound are mandatory. One table's rows at the root as
  \texttt{/entry}, a comma list as root children per table.
  Columns are properties (\texttt{datetime} as instants,
  \texttt{dynamic} decoded into subtrees with fallthrough);
  \texttt{::OperationId} is the correlation key; the default
  value is \texttt{Message} or the \texttt{Name}+
  \texttt{ResultCode} request line. Bearer token from
  \texttt{\$AZURE\_LOG\_TOKEN} or the az CLI
  (\texttt{QUARB\_AZ}); \texttt{endpoint=} overrides (the
  bottled \texttt{azlogs-server.py}). Read-only. Target:
  \texttt{azl:WORKSPACE?table=…\&since=1h\&limit=N} (alias
  \texttt{azlogs:}). \\
\texttt{quarb-cflogs} & Cloudflare edge logs, Logpull-shaped:
  \texttt{GET zones/\{zone\}/logs/received} NDJSON, one flat
  record per request, fields as properties under their own
  names plus minted \texttt{::ray} and \texttt{::timestamp};
  the default value is the request line; \texttt{:::cache} the
  cache status. \texttt{since=} is mandatory (Logpull demands a
  range; \texttt{until} clamps a minute behind now). The Ray ID
  is what the origin sees as \texttt{cf-ray}, so mounting the
  edge next to origin logs makes request reconstruction
  cross-provider — one \texttt{<=>} on the ray, another on the
  origin's own trace. \texttt{\$CLOUDFLARE\_API\_TOKEN};
  \texttt{endpoint=} replays Logpush archives (the bottled
  \texttt{cflogs-server.py}). Read-only. Target:
  \texttt{cfl:ZONE\_ID?since=1h\&limit=N} (alias
  \texttt{cflogs:}). \\
\texttt{quarb-ddlogs} & Datadog Logs through the v2 search API
  (\texttt{POST /api/v2/logs/events/search}, cursor-paginated):
  bounded snapshots (\texttt{since=}/\texttt{limit=} mandatory),
  \texttt{query=} as Datadog's own search syntax run
  server-side. Severity is Datadog's \texttt{::status} plus the
  family trait and ordered \texttt{:::severity} rank;
  \texttt{::trace} is minted from \texttt{dd.trace\_id}; tags
  split into fallthrough properties (\texttt{env:prod} answers
  \texttt{::env}); custom attributes navigate as children. Auth
  \texttt{\$DD\_API\_KEY}/\texttt{\$DD\_APP\_KEY}, site from
  \texttt{site=}/\texttt{\$DD\_SITE}; \texttt{endpoint=}
  overrides (the bottled \texttt{ddlogs-server.py}). Read-only.
  Target: \texttt{ddl:?since=1h\&query=…\&limit=N} (alias
  \texttt{datadog:}). \\
\texttt{quarb-github} & GitHub, three shapes in their native
  registers. The tree mirrors github.com URLs: users/orgs at
  the root (addressed by login — the root does not enumerate),
  repositories as their children, \texttt{files} /
  \texttt{issues} / \texttt{pulls} / \texttt{releases} sections
  below; file content and issue bodies are node values. The
  social graph is edge fabric, API-backed both ways:
  \texttt{follows}, \texttt{starred}, \texttt{owner},
  \texttt{parent} (\texttt{<-parent} = the forks),
  \texttt{author}/\texttt{assignee}, \texttt{org}, and
  \texttt{contributor} — the first adapter with true
  \texttt{backlinks}, and its contributor edge carries data
  (\texttt{\$-::contributions}). Counts and scalars are
  properties (\texttt{::stars}, timestamps as instants); flags,
  issue labels, and repo topics are traits (\texttt{<fork>},
  \texttt{<label:bug>}, \texttt{<topic:cli>}); an organization answers the
  \texttt{<org>} shorthand and the forge-neutral
  \texttt{<group>} alias. Direct addressing skips
  enumeration (\texttt{/rust-lang/rust/issues/12345}, closed
  included; listings show the API's default open set).
  Transport is \texttt{gh api} over subprocess
  (\texttt{QUARB\_GH} overrides); lazy, cached, read-only.
  Target: \texttt{github:[OWNER[/REPO]]}. \\
\texttt{quarb-gitlab} & GitLab, whose defining shape is the
  \emph{deep tree}: groups nest arbitrarily and mix subgroups
  with projects as children, which the REST API walks by
  URL-encoded full paths and the arbor restores to a path —
  \texttt{/tesslab/instruments/gauge/issues/7}, one GET per
  segment. Project sections: \texttt{files} (content as value),
  \texttt{issues} / \texttt{mrs} (the open sets; direct

  \texttt{\$-::access}, \texttt{\$-::role}), \texttt{parent} on

  \texttt{assignee} / \texttt{reviewer}. Labels (scoped

  Transport is \texttt{glab api} over subprocess
  (\texttt{QUARB\_GLAB} overrides; hosts via glab config), so

  \texttt{gitlab:[PATH]}. \\
\texttt{quarb-git} & The git repository driver: the object
  DAG as the arbor. \texttt{/branches}, \texttt{/tags},
  \texttt{/HEAD} (refs alias their commits — same properties,
  same children), \texttt{/commits} (rev-syntax aliasing:
  \texttt{/commits/'HEAD\textasciitilde2'} navigates without
  enumeration; \texttt{/commits/*} batches one
  \texttt{rev-list --all}). A commit's children are its
  \emph{tree} — time-travel file access, blob content as the
  node value. References are inherent:
  \texttt{::parent\textasciitilde>},
  \texttt{->parent} (merges fan out), \texttt{<-parent}
  (children, from the enumeration). The diff surface: tree
  entries carry the \texttt{<changed>} trait when their path is
  in the commit's diff vs its first parent (trees by prefix), so
  \texttt{git log -- path} is
  \texttt{/commits/*[/path<changed>]}; commits answer
  \texttt{::changed} (the touched paths, deletions included)
  and \texttt{:::n-changed}. Plumbing over subprocess —
  no libgit2, zero new dependencies. Target: \texttt{git:PATH}.
  Read-only. \\
\texttt{quarb-atrep} & The atrep semantic-document adapter —
  the OQL homecoming. Mounts a deltos (\texttt{.atd}) or kanon
  (\texttt{.atk}) \emph{through its dialektos}: sims named by
  their dialect names (\texttt{//section}, \texttt{//footnote}),
  genoses as traits, \texttt{::onym}/\texttt{::taxis}/
  \texttt{::lemma} projections, deixes and onym-monosims as
  typed crosslinks with a precomputed reverse index (the first
  adapter to prebuild both \texttt{links} and
  \texttt{backlinks}), \texttt{<dangling>} as a
  broken-cross-reference linter. Mounting runs
  \texttt{kanonizo::tasso} (ordering only — onyms stay as
  authored; transclusion stays visible as edges). Depends on
  \texttt{quarb} and \texttt{atrep}. \\
\texttt{quarb-serve} & The \emph{serve protocol} — the
  extension surface for tools the engine never links: a tool
  implements \texttt{AstAdapter} over its own model and hands it
  to \texttt{serve()} (three lines; non-Rust tools implement the
  protocol directly — nine operations over line-oriented JSON),
  and \texttt{qua serve:COMMAND} spawns it and mounts it beside
  every other source. LSP's shape: the protocol is the plugin
  system. Two wires, one protocol: the handshake is JSON (the
  universal floor) and advertises formats; every first-party
  server offers \emph{kaiv} (\texttt{.daiv} frames, natively
  typed leaves under \texttt{/@serve}) and the client upgrades
  to it — the house format is the default wire, JSON the
  foreign-tool floor. Read-only by construction (no mutating
  operation exists). First external user: \texttt{cuj quarb-serve}
  (the cuj vault, mounted without qua knowing cuj). Reference
  server: \texttt{quarb-serve-json}; identity-tested against the
  direct adapter. \\
\texttt{quarb-sql} & The SQL bridge, both directions:
  \texttt{translate} imports a \texttt{SELECT} statement (WHERE,
  one JOIN via correlation and the witness, GROUP BY/HAVING,
  ORDER/LIMIT/DISTINCT, \texttt{LIKE} as case-insensitive
  regexes), and \texttt{export} walks a Quarb query's reflection
  arbor back to \texttt{SELECT} — witness joins become
  \texttt{JOIN ... ON}, grouped reductions become \texttt{GROUP
  BY}/\texttt{HAVING}; \texttt{\textasciitilde>} chains are
  refused by design (foreign keys live in the schema, not the
  query — spell \texttt{<=>} to export). Both directions
  differentially tested against SQLite; binaries
  \texttt{sql2quarb} / \texttt{quarb2sql}. \\
\texttt{qm} & The mailbox interface for the terminal — the
  first \emph{library-path} client beside \texttt{qua}: it opens
  the Maildir adapter once per invocation, addresses messages as
  node handles, and phrases its subcommands (\texttt{ls},
  \texttt{read}, \texttt{thread}, \texttt{from}, \texttt{grep},
  \texttt{count}) as queries where a query is the natural shape,
  with \texttt{qm query} as the raw escape hatch. Actions are the
  tool's, not the engine's: \texttt{qm seen} performs the Maildir
  flag rename itself on the file handle the adapter exposes
  (\texttt{path\_of}). \\
\texttt{qua} & The command-line tool. Picks the adapter from its
  argument (a directory is filesystem; \texttt{.csv}/\texttt{.tsv}
  is a table; a file or piped stdin is XML by extension or a leading
  \texttt{<?xml}, HTML by extension or a leading \texttt{<}, else
  JSON) and prints results. \texttt{--xpath} / \texttt{--jq} / \texttt{--sql}
  translate the query from XPath, jq, or SQL first; database
  inputs get \emph{pushdown} — a query whose constructs are all
  in the verified-safe set (filtered selections, whole-table
  aggregates, witness joins) compiles to SQL and runs on the
  server, with rows ordered by the catalog key so output is
  identical to the scan path (\texttt{--no-pushdown} opts out;
  any refusal or error falls back silently, and
  \texttt{--explain} prints the decision — the pushed SQL, or the
  construct that kept the query on the scan path). When full
  pushdown refuses, \emph{partial} pushdown pushes the leading
  row predicates as the table's fetch filter and runs the original
  query over the reduced set (gated: single reach, no
  crosslink/resolution axes, no metadata — anything that could
  observe the filtering). \texttt{--save FILE} materializes a
  result — \texttt{.db}/\texttt{.sqlite} as a table
  (\texttt{--as} names it), \texttt{.json} as a JSON array —
  both first-class inputs for later queries (the reference syntax
  is the existing file/mount mechanism); \texttt{--daiv} emits
  canonical kaiv (typed leaves with per-value provenance; needs the
  sibling \texttt{kaiv-rs} checkout). \\

\medskip

Adapters are separate crates by design: \texttt{quarb-fs},
\texttt{quarb-json}, \texttt{quarb-html}, and \texttt{quarb-xml}
share nothing but the \texttt{AstAdapter} trait, and a consumer
pulls in only the adapters it needs. Each new adapter has confirmed
the surface without changing it\,---\,the filesystem, a JSON tree,
an HTML DOM, and an XML document are genuinely the same arbor to
the engine.

\section{The Layers of the Engine Crate}\label{sec:layers}

The \texttt{quarb} crate is one crate in layers, each a directory
under \texttt{quarb/src/}, each allowed to reference only the layers
below it:

\begin{xltabular}{\textwidth}{l X}
\toprule
\textbf{Layer} & \textbf{Holds} \\
\midrule
\texttt{value} & The value space: null, bool, int, float, text,
  list, record, table, foreign; numbers, quantities, locales,
  transliteration, encodings. What an AST literal holds. No node. \\
\texttt{syntax} & The language as text and tree: lexer, parser,
  AST, unparser, highlighter, completion, the function registry.
  One grammar for the calculator and the graph language. \\
\texttt{stdlib} & The functions over values, reached by name from
  a call, with the arithmetic and comparisons the operators run. \\
\texttt{thread} & The forking machine: a list of threads and three
  moves (fork, terminate, the whole-list map); every layer above
  hangs its own per-thread state on the thread, copied on a fork
  and never shared afterwards. \\
\texttt{pipeline} & Commands, control operators, bodies,
  environments, the registry and memo of a run, provenance. \\
\texttt{graph} & Arbors, anchors, steps, correlation, adapters,
  identity, tabula reading, reflection, the trace. Everything
  that knows a node. \\
\bottomrule
\end{xltabular}

\texttt{lib.rs} is the facade above all of them: the public paths
(\texttt{quarb::adapter}, \texttt{quarb::Value}, \texttt{quarb::run},
\ldots) are re-exports and did not move. The dependency direction is
checked, not assumed: \texttt{scripts/layers.py} resolves every
\texttt{crate::} path in a layer's files to its layer and fails on a
reference upward that \texttt{scripts/layers-debt.txt} does not
record. The record is the debt still being paid and is meant to
burn down to nothing; a change that adds an upward reference fails
the check, and one that removes some must update the record in the
same commit. Six references remain: the parser's default reflector
(a test convenience), the library's two kaiv arms, and the graph
tests' reach into the facade.

\paragraph{The thread and its attachment.} The thread
(\texttt{thread/mod.rs}) is generic over what the layer above hangs
on it: \texttt{Thread<X>} carries a register, a topic with its
provenance, the members of a group, the captures of the last match,
and one \texttt{ext: X}. The \texttt{Attachment} trait names what a
scope may see of the attachment beside the attachment itself: a
\texttt{View} (the graph's: whether the thread stands on a node), a
\texttt{Crossing} (the edge a hop is crossing, for \texttt{\$-}), a
\texttt{Witness} (what a correlation search tries in place of the
thread's own bindings), and a \texttt{Key} (what a context is indexed
by). The calculator's attachment is the unit type, so a calculator
thread is the register and the topic and nothing else. The graph's
is \texttt{GraphExt} (\texttt{graph/navigate.rs}): the node, the
correlation bindings and the arrived edges, and the capsa of the
spec is \texttt{Thread<GraphExt>}. The walk's frontier carries one
attachment per path, so a predicate pass borrows it and clones
nothing. A \texttt{Position} is a number the thread and the pipeline
carry and compare; only the graph reads it as a node.

The register is the whole memory (spec: The Capsa): one sequence of
regulae, a regula any value, node references included. A mark
\texttt{.name} files a reference to the position
(\texttt{Value::Node}, minted by \texttt{graph::navigate::node\_ref}
with the node's coordinate and its locator), so there is no mark
store beside the register and one name pool over both kinds. The
reads split by side: \texttt{\$.} \texttt{@.} \texttt{\%.}
\texttt{\%.*} see the regulae that are not references, \texttt{\$\$.}
\texttt{@@.} \texttt{\%\%.} \texttt{\%\%.*} the references, positions
counting on each side; a name reads whatever was filed under it last
(\texttt{pipeline/register.rs}). The dedup key of a walk is the node
and the merged sequence, so the interleaving of values and
references is part of a thread's state. The cursor is the scope's
business, not the thread's: \texttt{\$\$\_} (\texttt{Operand::Position})
reads the node the scope stands on, \texttt{\$\$\_\_}
(\texttt{Operand::Invoking}) the scope's \texttt{outer}, set when a
query body opens, and \texttt{\$\$0} (\texttt{Operand::Driver}) the
scope's \texttt{driver}, set by the join condition alone and refused
by the parser anywhere else. Bare, each is a reference; a reference
read as a value prints and exports as its locator, equals a
reference to the same node, and resolves to it under \texttt{-->}.

\paragraph{The host.} The pipeline evaluates commands and operands
against a \texttt{Host} (\texttt{pipeline/mod.rs}), the trait that
holds every question the pipeline cannot answer from a value alone:
the root attachment, a property of a node, the provenance at a
position, a node's scalar, its rendering as JSON, XML or a table,
the navigation of a step, the edges of a node. Every adapter is a
host (\texttt{graph/host.rs} implements the trait for any
\texttt{AstAdapter}), and so is the calculator's \texttt{Calc},
whose attachment is the unit and whose node questions are refused by
name. The generic operand evaluator (\texttt{pipeline/operand.rs})
runs on any host; the graph keeps the node-reading half
(\texttt{graph/operand.rs}) and wraps the generic one with a witness
slot for correlation. The registry tags every command with the
layer its answer comes from (\texttt{Layer::Value} or
\texttt{Layer::Node}); the calculator's entry refuses a pipeline
that names a node command before it runs, as it refuses a head that
is not bare.

\paragraph{The parser's reflector.} The parser expands macros
through an \texttt{Expander} (\texttt{syntax/expand.rs}), a trait
with the usage questions a macro body needs answered; the graph's
\texttt{Reflector} implements it over an optional adapter, so the
syntax layer never names the evaluator. The ambient state a run
needs below the pipeline (the collation, the sentence bonds, the
refusal channel the library reports into) lives in
\texttt{value/ambient.rs} as a stack entered per run; the run
options the graph adds (the plan, the budget, the reference targets)
stay in \texttt{graph/run.rs}.

\section{The Execution Ladder}\label{sec:ladder}

Database adapters evaluate on a three-rung ladder; every rung is
\emph{output-identical} to the one below it (differential tests
hold this), so the rungs trade only latency and transfer:

\begin{enumerate}
  \item \textbf{Full pushdown} (\texttt{quarb\_sql::pushdown},
    the exporter's strict mode): the whole query compiles to SQL
    when every construct is in the verified-safe set —
    WHERE-filtered selections, whole-table aggregates, witness
    joins. Strictness is the point: anything whose SQL semantics
    are not provably identical (LIKE case folding, truthiness,
    GROUP BY/DISTINCT order, collations, unordered LIMIT) refuses.
    Row order is part of the contract — the plan names the result
    table, and each driver appends \texttt{ORDER BY} its key from
    the catalog. Column types are part of it too: Quarb compares
    by value (numeric-looking text meets a number as a number, a
    number and other text never meet), SQL by the column's type,
    and SQLite and MySQL coerce a mixed comparison by rules of
    their own. A numeric-looking \emph{text} literal therefore
    never pushes; for the rest the plan records what it assumes
    (\texttt{ColumnTypes}: the columns it compares with a number,
    those it compares with text), and \texttt{qua} asks the
    driver's catalog (\texttt{column\_catalog}: SQLite's
    affinity, MySQL's \texttt{data\_type}) before using a plan,
    full or partial; an unmet assumption scans, and
    \texttt{--explain} names the column. The strictly typed
    engines reject the mismatch themselves, which falls back the
    same way. What remains outside: a SQLite cell that violates
    its column's declared type. Measured: COUNT over 500k
    PostgreSQL rows, 2.57\,s scanned vs.\ 0.018\,s pushed.
  \item \textbf{Partial pushdown}
    (\texttt{quarb\_sql::partial\_pushdown}): the leading run of
    strictly-translatable row predicates becomes the table's fetch
    filter (each driver's lazy fetcher accepts a per-table WHERE),
    and the \emph{original} query runs unchanged over the reduced
    set — the engine re-applies the pushed predicates, a no-op on
    pre-filtered rows, so there is no query rewriting. Gates:
    leading run only (a positional predicate before an expression
    one sees unfiltered rows), a single \texttt{/table/*} branch
    with no correlations, the table reached exactly once, no
    crosslink/resolution axes, no \texttt{:}/\texttt{:::}
    metadata (each would observe the filtering). Since the
    JSON-column round (2026-07-31), refused predicates in the
    leading run degrade to \emph{superset prefilters} instead
    of aborting the plan: fixed-path JSON comparisons emit
    per-dialect forms proven never to drop a matching row
    (SQLite typed extract with a \texttt{json\_type='text'}
    escape hatch, PostgreSQL \texttt{jsonb\_typeof} CASE with
    \texttt{::float8}; existence and \texttt{!=} floor at
    \texttt{json\_type IS NOT NULL}) — extras are re-checked
    by the re-run, and a server-rejected prefilter surfaces
    through an eager prefetch and falls back to the scan
    rather than answering empty. Full JSON string-equality
    pushdown carries the dialect's validity guard
    (\texttt{json\_valid} and kin) and refuses
    numeric-looking literals (Quarb's \texttt{value\_eq}
    coerces those numerically; no extractor matches that).
    Measured: unpushable grouping over a 1\%-selective filter,
    2.31\,s vs.\ 0.081\,s; JSON numeric compare over 200k
    rows, 1.46\,s scanned vs.\ 0.25\,s prefiltered.
  \item \textbf{Lazy scan}: catalog-eager, rows-lazy per table
    (Section on \texttt{quarb-relational}); correct for
    everything, always the fallback.
\end{enumerate}

\noindent
\texttt{qua --explain} prints the decision chain; \texttt{qua
--no-pushdown} pins the scan rung; \texttt{qua --save FILE
[--as NAME]} materializes any result as a first-class input
(\texttt{.db} table / \texttt{.json} array) so expensive
reductions run once and iteration proceeds locally. For metered
engines (a future BigQuery adapter bills by bytes scanned), the
ladder's transfer reductions are cost reductions.

\medskip

The pipeline runs on \emph{capsae}\,---\,the register system's unit,
a node paired with a register (its breadcrumbs, node references
among them) and a current topic. A per-capsa \texttt{|} transforms
each topic; \texttt{@|} reduces the whole context; \texttt{| .name}
pushes the topic onto the register (a reference to the position
where there is no topic) and \texttt{| \$.name} recalls it; a
subcontext \texttt{| .(expr)}
evaluates \texttt{expr} from each node, reduces it to a scalar, and
pushes it\,---\,grouped aggregation without leaving the query. A
push of any spelling appends to the capsa and leaves the cursor as
it is (spec draft 154): the topic before \texttt{| .n(expr)} is the
topic after it, the value waits in the register for
\texttt{\$.n}, and a query ending in a push yields its topics as
they stood (\texttt{pipeline\_projected} treats no push as
value-typing). The context family reads the command's input
snapshot (spec draft 157): \texttt{@\_} the peers' topics,
\texttt{@@\_} their positions (\texttt{Host::positions}; a glued
projection maps over them), \texttt{\#.*} and \texttt{\#\#.*} the
context as a table of the value or the node regulae
(\texttt{pipeline::operand::matrix}, one row per thread, the columns
as \texttt{\%.*} names them, typed by the table rule; \texttt{\#.} and \texttt{\#\#.} the named regulae alone); the old
\texttt{@*} refuses with the pointer. A
push quantified \texttt{\{N\}} repeats over the whole context, each
round seeing the last (the iteration loop); \texttt{X:.r} reads the
register of whichever capsa stands at the node \texttt{X} reaches,
from the same snapshot; and every value remembers where it was
read, so \texttt{:} on a value answers its provenance the way
\texttt{:} on a node does.

\medskip

Any other operator is lexed and rejected with a
\texttt{not yet supported} error naming the offending construct,
rather than silently mis-parsed. Everything in
Section~\ref{sec:planned} falls into this category today.


\chapter{The Adapter Surface}\label{ch:adapter}

An \emph{adapter} maps a data source onto the Quarb arbor model\,---\,a
tree backbone whose edges carry \emph{names}, enriched with
non-hierarchical crosslinks. The engine drives all navigation through
the \texttt{AstAdapter} trait, so this trait \emph{is} the contract
between the language and the world.

One clause of that contract concerns the values an adapter mints
(spec: adapter responsibilities, draft 155): a property that
\emph{measures} something is a quantity in the source's own unit\,---\,a
size through \texttt{Value::bytes}, a span of time through
\texttt{Value::seconds}, a length as a \texttt{Value::Quantity} written
in millimetres or kibibytes as the source keeps it\,---\,and a count
stays a number. A bare number never compares with a quantity (a
threshold names its unit, \texttt{[::size > 40\_B]}), so a measure
minted bare would be unreachable from a criterion.

A second clause concerns traits (spec: adapter traits, draft 156). A
relational cell carries its column's declared type, lowercased and
stripped of parameters (\texttt{<varchar>}, \texttt{<integer>}), and
beside it the derived kind \texttt{<number>}, \texttt{<string>} or
\texttt{<boolean>}; the one implementation is
\texttt{quarb\_relational::type\_traits} over the
\texttt{TableSpec::column\_types} each driver fills from its catalog
(PRAGMA \texttt{table\_info}, \texttt{information\_schema}, Oracle's
\texttt{user\_tab\_columns}). A file carries its lowercased extension
beside its class (\texttt{<json>}, \texttt{<tgz>}; \texttt{.tar.gz}
carries \texttt{<gz>} and \texttt{<tar>}), so the leaf of the file
system and the root of the grafted document say what they are alike.

pub struct NodeId(pub u64);

pub trait AstAdapter {

    fn root(&self) -> NodeId;

    /// The tree children of `node`, in document order.
    fn children(&self, node: NodeId) -> Vec<NodeId>;

    /// `None` when the adapter leaves a node unnamed (e.g. the
    /// filesystem root).
    fn name(&self, node: NodeId) -> Option<String>;

    fn default_value(&self, _node: NodeId) -> Option<Value> { None }

\noindent
The navigation methods are required; the projection methods carry
defaults, so an adapter implements only what its domain offers. Core
metadata (\texttt{:key}\,---\,index, depth, counts, \texttt{is-leaf},
\dots) is computed by the engine from the navigation surface, so no
adapter implements it.

Three observations that the filesystem work has already forced:

\begin{itemize}
\item \textbf{Names live on edges, not nodes.} \texttt{name} returns
  the label of a node's \emph{incoming} edge\,---\,its role in its
  parent\,---\,exactly as the specification's edge-name model
  requires. For the filesystem this is simply the filename.

\item \textbf{\texttt{NodeId} is opaque and adapter-private.} The
  engine never inspects the \texttt{u64}; it only passes ids back to
  the adapter. Each adapter chooses its own identity scheme (the
  filesystem adapter uses an interning arena index).

\item \textbf{New trait methods need their forwarders.} The run
  path wraps adapters in layers (the decoding \texttt{Sourced}
  layer), the session in \texttt{Dyn}, mounts in
  \texttt{MountAdapter}/\texttt{Shared}, models in
  \texttt{ModelAdapter} -- a defaulted method silently answers
  \texttt{None} through any wrapper that does not forward it.
  The plain wrappers (those that override at most a method or
  two) write their forwarding with
  \texttt{quarb::forward\_ast\_adapter!(FIELD; except m, \ldots)},
  whose method table is checked against the trait by a test in
  \texttt{adapter.rs}, and a probe adapter is run through each
  shipped wrapper -- so a new trait method is forwarded by all
  of them once it is added to the table. The composing wrappers
  (\texttt{MountAdapter}, \texttt{ModelAdapter}, the graft, the
  reflection views) still forward by hand: when adding to the
  trait, sweep those. The
  case in point (2026-09-07): \texttt{Dyn} had never forwarded
  \texttt{answers\_to}, so a web level behind the session's
  boxed door answered \texttt{//page} with nothing -- its rows
  answer to their kind through that method. The sweep of 2026-10-06 found three hooks
  no wrapper forwarded (\texttt{descendants\_where},
  \texttt{has\_node}, \texttt{provenance\_list}), and
  \texttt{ModelAdapter} dropping \texttt{link\_property} and
  aliased metadata, so an edge property or \texttt{:::size}
  answered nothing under \texttt{--model}; the macro round of
  2026-10-07 found the Python binding's \texttt{Dyn} forwarding
  29 methods of 45. A model's mount
  targets stay relative to its own file (the tool resolves
  them once, against the file it was given), so a
  \texttt{use}d model's targets are carried over by the
  \texttt{use} path as written.

\item \textbf{Integers compare as integers.} Two integers are
  compared, keyed for joins and \texttt{unique}, and sorted
  exactly; the float reading enters only when one side is not
  an integer (\texttt{SortKey::Line} carries the integer beside
  the float, and $-0.0$ keys as $0.0$). Above $2^{53}$ the float
  reading alone would merge neighbours.

\item \textbf{The core is smaller than the crate.} The temporal
  fragment (instants, durations, periods, time expressions, the
  calendar names) is the \texttt{quarb-time} crate, re-exported by
  \texttt{quarb} at its old paths (\texttt{quarb::temporal},
  \texttt{period}, \texttt{timex}). Three features, on by
  default, carry what one function needs: \texttt{decode-formats}
  (the structured readings of \texttt{decode}: serde\_json,
  serde\_yaml\_ng, toml, quick-xml), \texttt{kaiv} (the kaiv
  output of \texttt{| kaiv} / \texttt{@| kaiv}), \texttt{desm}
  (syndesmos as the session's sentence bonds). Off, the function
  refuses with the feature's name. The sentence bonds themselves
  are a trait (\texttt{quarb::SentenceBonds}): the engine segments
  through whatever the tool set, syndesmos or another.

\item \textbf{The plan is read before the run.}
  \texttt{Query::plan(\&adapter)} (\texttt{quarb::plan}) reads
  off the syntax tree, per branch and per step, the axis the fast
  path covers, the literal name, the equality conjuncts lowered,
  the literal path to the step's base where every step before it
  was a bare child hop by name, and what the adapter says from its
  catalog: \texttt{select\_plan} (which conjuncts it would apply)
  and \texttt{estimate} (nodes, bytes, requests, latency,
  confidence), composed along a branch (\texttt{Estimate::then})
  and across branches (\texttt{beside}), unknown where no
  estimator answers. \texttt{Plan::roots} names the first child of
  every anchored branch -- under a mount table, the mounts the
  query touches; an unanchored search is every mount. A
  \texttt{Run} may carry a \texttt{Budget} (nodes, bytes,
  requests; \texttt{strict} refuses an unknown estimate): a query
  the estimate puts beyond it is refused before anything runs, and
  the \texttt{Outcome} carries the plan. \texttt{Plan::to\_kaiv}
  emits it as a \texttt{quarb/plan} payload (\texttt{qua --plan}
  prints it and stops; \texttt{qua --budget nodes=N,bytes=N}).
  \texttt{Model::reachable\_roots(named)} (quarb-model) closes a
  set of mounts over the \texttt{ref}, \texttt{rel} and
  \texttt{tree} declarations, for a replay plan. The relational
  model takes a driver's \emph{estimator}
  (\texttt{RelationalModel::with\_estimator}: the table and the
  plan's column equalities in, an \texttt{Estimate} out, asked
  once per run per table and equalities): BigQuery prices the
  statement with a dry run (bytes exact, a bound for a clustered
  table) and reads the row count from \texttt{tables.get};
  Postgres, MySQL and Oracle ask their planners
  (\texttt{EXPLAIN}, \texttt{EXPLAIN FORMAT=JSON}, \texttt{EXPLAIN
  PLAN}); SQL Server reads \texttt{sys.partitions}; DuckDB its
  catalog's \texttt{estimated\_size}; Athena the table's
  crawler properties; SQLite \texttt{sqlite\_stat1} after
  \texttt{ANALYZE}, unknown without it. The SQL adapters forward
  the whole trait through \texttt{forward\_ast\_adapter!}, so
  \texttt{select}, \texttt{count}, \texttt{select\_plan} and
  \texttt{estimate} reach the model.

\item \textbf{A mount may be latent.} The mount adapter declares a
  mount by name, target and opener (\texttt{MountAdapter::declare})
  and opens it the first time a query reaches it: a hop by its
  name, a listing of the root's children (so an unanchored
  \texttt{//x} opens every mount before the scope memo is built),
  a reference landing on a declared identity. \texttt{tree\_identities}
  answers a latent mount from its declaration with a stand-in root
  id that opens the mount when touched; the every-mount hints read
  the active set. A failed opener is a refusal and an empty mount.
  A live table takes new mounts (\texttt{push}) and identities
  (\texttt{declare\_identity}). A declaration may carry a
  \texttt{catalog} closure: what the target holds before it is
  opened, so the plan prices a step from the mount's root while
  the mount is latent.

\item \textbf{A catalog prices a source before it is read.}
  \texttt{quarb::Catalog} is substrate-neutral — entries and
  bytes as a range, a latency, a confidence — and every substrate
  states one cheaply: \texttt{quarb\_archive::catalog} from a
  zip's central directory or a tar's headers, \texttt{quarb\_open::catalog}
  from a bounded directory listing or a file's size, a warehouse
  from its dry run. \texttt{Estimate::from\_catalog} turns it
  into a root step's estimate as bounds (entries are files or
  members, the estimate counts nodes: a child step reaches at most the
  entries, an unfiltered descendant step at least every entry),
  the catalog is a lookup by literal path
  (\texttt{CatalogLookup}: a folder's own listing, one member's
  header), so \texttt{Estimate::at\_catalog} narrows the price
  to the path the plan records — a bare hop by name is one entry,
  the reading step under it is priced by that entry's catalog, a
  path the catalog cannot place (a node inside a document) is a
  bounded unknown under the whole; a mount table prices a root
  step across its mounts; a database file is left to its store's
  estimator once open, and a hop by name under a table is a row
  by key, at most one. The plan lowers the leading predicate as a
  comparison (\texttt{Conjunct::Compare}: any operator, any
  literal; a text equality stays \texttt{Equals}, the index's) and
  the step's trait filters, and asks the catalog with them
  (\texttt{Ask}): a listing applies \texttt{::size} and
  \texttt{<file>}/\texttt{<dir>} before counting and says so
  (\texttt{Catalog::applied}), a store's statistics price an
  equality on an indexed column (SQLite: \texttt{sqlite\_stat1}'s
  rows per key); what a catalog cannot apply leaves the whole
  count as the bound; \texttt{quarb::Unopened} is an adapter
  that is only its catalog, for planning and budgeting without
  opening (\texttt{qua --plan} / \texttt{--budget} price every
  path input this way first). Once open, an in-memory adapter
  answers \texttt{estimate} through \texttt{adapter::arena\_estimate},
  a counted walk of its own nodes (JSON, CSV, XML, HTML, text,
  fs, archive), bounded past two million nodes. An upper end of
  \texttt{u64::MAX} means unbounded: a lenient budget passes it, a
  strict one refuses. The budget's cap (\texttt{Budget::cap},
  carried as \texttt{StepPlan::cap} and handed to every catalog
  producer) short-circuits the pricing itself: a listing, a tar
  header walk or an arena count stops at the first entry past the
  budget and reports a lower bound that already exceeds it, so
  pricing a directory of a hundred thousand files under
  \texttt{nodes=1000} costs a thousand reads and one. Pricing is
  opt-in: a run with neither \texttt{plan} nor a budget never
  asks an adapter for an estimate and never reads a catalog, so
  the default path runs the query straight, at no planning cost.

\item \textbf{The conformance suite is the contract's test.}
  \texttt{quarb::conformance::check(\&adapter, budget)} walks a
  sample of an adapter's nodes and names every pair the engine
  relies on that the sample breaks: a child's \texttt{parent},
  \texttt{has\_node}, \texttt{answers\_to} its own name,
  \texttt{children\_named} and a child \texttt{select} finding
  it, \texttt{has\_trait} over \texttt{traits},
  \texttt{property\_names} over \texttt{properties},
  \texttt{provenance\_list}'s first entry, a descendant
  \texttt{select} against the walk. An adapter's tests call it on
  a fixture and assert the list is empty (the JSON and HTML
  adapters do); an index that answers short is caught there, not
  by a query.

\item \textbf{The shell gate is checked twice.} The static walk
  refuses a query that names \texttt{sh(...)} or a backtick
  command anywhere it can stand (record fields, list items and
  field bases included); the executor refuses the command again
  when it runs, so a path the walk does not know cannot reach
  the shell without \texttt{--allow-shell}.

\item \textbf{A child's standard input is fed from a thread
  with SIGPIPE blocked.} The shell command and the environment
  commands write the topic (or the context's lines) to the child
  from a thread of their own, so the parent drains the child's
  output meanwhile (\texttt{env::feed\_stdin}). A child that stops
  reading early~--- \texttt{head}, a program that fails~--- closes
  the pipe under the writer; with the signal blocked on that
  thread the write fails with EPIPE and the call takes its proper
  outcome (null, or a refusal over the context), where the
  default disposition \texttt{qua} restores for its own stdout
  would kill the whole process silently (exit 141). Found by
  feeding \texttt{@| u:head(-n=3)} a novel.

\item \textbf{What a run is given is the run's, never the
  adapter's.} The invocation instant \texttt{now()} denotes, the
  shell gate, the quantifier and frontier bound overrides, reproducible
  provenance, the reference targets, the output collation and the
  sentence bonds travel in a \texttt{quarb::Run}; a tool parses a
  \texttt{Query} once (data-aware macros expand under the same
  \texttt{Run}) and runs it as often as it likes, each run
  answering an \texttt{Outcome} (the result, the closing table
  taken off for rendering, the unresolved references). The
  executor reads the options from the run in progress, and a run
  begun from inside another -- an adapter answering through the
  engine, a model's constructor queries -- inherits them, so
  nothing rides on an adapter method or a global. The adapter
  keeps only \texttt{quantifier\_bound}, the depth its own
  structures need (metatheca's chain), which a run may override.
  The convenience entries (\texttt{quarb::run} and its
  \texttt{\_with\_defs} / \texttt{\_traced} twins) run under the
  ambient options: the instant the tool pinned, the bonds it set,
  the gate closed.

\item \textbf{The root may be unnamed.} \texttt{name} returns
  \texttt{Option} precisely so an adapter can leave the root without a
  name, as the filesystem root \texttt{/} does.

\item \textbf{A failed fetch is a refusal, never an empty answer.}
  The trait has no error channel below the entry points, so a read
  that fails inside an evaluation\,---\,a table load, a label
  listing, a relationship fetch, a count, a paginated listing cut
  off mid-way\,---\,records a refusal
  (\texttt{quarb::record\_refusal}; \texttt{quarb::fetched} /
  \texttt{fetched\_opt} wrap a \texttt{Result} that way) and the
  query errors with the adapter's message. A listing that failed is
  left uncached, so the next query reads again. The one legitimate
  emptiness is the server's own word\,---\,LDAP's
  \texttt{noSuchObject} and \texttt{insufficientAccessRights}.

\item \textbf{Bounds where data set the size.} Every bound refuses
  with a message naming it: nesting (\texttt{MAX\_NEST}, carried
  into holes, expansions and generated text), \texttt{repeat} /
  \texttt{indent} (\texttt{MAX\_REPEAT\_BYTES}, 64 MiB), outline
  levels (\texttt{MAX\_OUTLINE\_DEPTH}, 64 below the shallowest),
  unit exponents (\texttt{MAX\_EXPONENT}, 32), mounts
  (\texttt{MAX\_MOUNTS}, 254: \texttt{MountAdapter::try\_new}),
  what an archive may decompress into memory
  (\texttt{MAX\_ARCHIVE\_BYTES}, 1 GiB, an xz stream checked
  against its index first). The executor's tree walks run on an
  explicit stack, so a source's depth is never the thread's.
\end{itemize}

\section{The Source Boundary}\label{sec:source-boundary}

Text is text inside the language; bytes meet it at two boundaries,
both the engine's, in \texttt{quarb::source}. An adapter decides
nothing about encodings.

\begin{itemize}
\item \textbf{Decoding} (\texttt{source::decode}, carried by a
  \texttt{SourceDecoding} per mount): \texttt{?encoding=LABEL} on the
  mount, then a byte-order mark, then the declaration the format's
  reporter finds in the bytes, then strict UTF-8\,---\,a source that
  reaches the last step and is not valid UTF-8 is refused, naming
  the option. Nothing is guessed from bytes and nothing is decoded
  lossily; within a decided encoding a malformed sequence becomes
  U+FFFD and is counted. Labels are the Encoding Standard's
  (\texttt{encoding\_rs}); the CJK tables ride the \texttt{cjk}
  feature of \texttt{quarb} (on for \texttt{qua}, off for the
  playground and the extension).
\item \textbf{Reporters} are plain functions over bytes in the
  adapter crates: \texttt{quarb\_xml::declared\_encoding} (the
  prologue; the reader itself is
  \texttt{quarb::source::xml\_declared\_encoding}, shared with
  the packages), \texttt{quarb\_html::declared\_encoding} (the meta
  charset prescan), \texttt{quarb\_maildir::declared\_encoding} (the
  MIME charset of a message's own headers). A host chooses the
  reporter by the source's name
  (\texttt{quarb\_compose::declared\_encoding}); the adapter never
  decodes.
\item \textbf{Layers that read bytes} take the rule and answer for
  what they decoded: \texttt{Sourced} (the wrapper \texttt{qua}
  puts on a mount it read itself) answers \texttt{:::encoding} and
  \texttt{:::replaced} on the root; \texttt{ComposeAdapter}
  (\texttt{with\_decoding}) reads a grafted leaf through its path
  and answers on that leaf; \texttt{ArchiveAdapter}
  (\texttt{open\_with\_decoding}) on each member it reads, tar
  and zip names included (an entry name is bytes under the rule,
  never the format's CP437 guess; zip members are read by index, so
  a decoded name need not match the library's);
  \texttt{MaildirAdapter} / \texttt{ImapAdapter} per message;
  \texttt{quarb\_web::fs::open\_dir\_with\_decoding} per page;
  \texttt{GitAdapter} / \texttt{MetathecaAdapter}
  (\texttt{open\_with\_decoding}) on a blob (one that decodes
  under none has no text; git's own structured output must be
  UTF-8, paths unquoted and messages transcoded by
  \texttt{--encoding=UTF-8}); the packages\,---\,docx, odt,
  epub\,---\,on each XML member through
  \texttt{parse\_with\_decoding} (the option, a byte-order
  mark, the member's XML prologue, else strict UTF-8; a member
  that decodes under none is an error naming it, never a part
  silently missing); \texttt{TreeSitterAdapter} /
  \texttt{CodeModel::open\_with\_decoding} and
  \texttt{quarb\_text::read\_conllu\_dir\_with} on a source
  file. A response body over HTTP is read whole under
  \texttt{source::text\_from\_reader} (a 256 MiB bound, strict
  UTF-8\,---\,the wire formats are UTF-8 by their standards), never
  cut at a client library's cap nor replaced.
\item \textbf{Delimited text} is decided the same way, never
  sniffed: \texttt{CsvAdapter::parse\_declared} takes
  \texttt{?delimiter=} off the mount (\texttt{CsvOptions}), else an
  Excel \texttt{sep=X} first line, else the extension's default; a
  header without the decided delimiter but another candidate
  throughout is refused naming the option. Numbers in text read in
  the canonical form (\texttt{quarb::number}: digits, sign,
  \texttt{.}, exponent; grouped thousands under the default
  convention); a source that writes decimal commas declares
  \texttt{?decimal=comma} and its cells with a reading arrive in
  canonical form, so every reading downstream agrees.
  \texttt{| number(LOCALE)} reads text under a locale's convention
  from a small embedded table; \texttt{@| csv(";"; …)} takes the
  delimiter as a quoted first operand (the parser carries it as
  \texttt{delimiter=;}).
\item \textbf{Dates in a locale's words}: \texttt{strptime(fmt;
  LOCALE)} / \texttt{tp} and \texttt{strftime(fmt; LOCALE)} /
  \texttt{tfmt} read and write the \texttt{\%B \%b \%A \%a} names
  from \texttt{quarb::datenames}, a small embedded CLDR table (by size
  of language: en, zh, es, ar, pt, ru, ja, de, fr, tr, it) listing every form a locale writes
  (the date form \texttt{октября}, the stand-alone
  \texttt{октябрь}, the abbreviations); every form parses, case
  folded, longest first, and writing takes the date form where
  the format carries a day (\texttt{\%d}, \texttt{\%e}) and the
  stand-alone form where it does not (\texttt{\%B \%Y}: октябрь
  1899). Format
  literals match as written (\texttt{'\%d \%B \%Y г.'}). Without a
  locale the English names; a locale with no table refuses. The
  temporal reading of bare text stays ISO-8601.
\item \textbf{Periods and time expressions} (spec: Time
  Expressions and the Timeline). \texttt{Value::Period} is a
  start second and a grain (\texttt{quarb::period}: year to
  second, ISO-8601 at reduced precision in print and in the
  interchange forms). The \emph{calendar reading}
  (\texttt{Value::calendar\_reading}) reads a period, reduced
  or full ISO text, an integer as a year, an instant at its
  printing grain. \texttt{value\_eq} / \texttt{value\_cmp} test
  for a period operand first and compare as intervals: nested
  periods are equal, disjoint ones ordered. A period has its
  own sort key (start, then the coarser first), no equality key
  (a search takes the scan), no numeric reading (arithmetic is
  null), and reads as its first instant wherever a command
  goes through the temporal reading. \texttt{period([GRAIN])}
  and \texttt{grain} are scalar commands.
  \texttt{timex(LOCALE)} (\texttt{quarb::timex}) is an
  expanding scalar command like \texttt{words}: one record
  per expression. Recognition is a list of templates per
  locale (\texttt{timexdata.rs}, the eleven locales of the
  date names), each a regular expression over slots
  (numeral, unit, month, weekday, day, year, clock, part of
  day) compiled once per locale. The earliest match wins,
  then the longest, then the rule listed first, and an
  overlapping match is dropped. Widening a list is the whole
  of teaching the reader an expression. No stemmer and no
  tagger takes part. Digits of other scripts, the
  typographic apostrophe and the Turkish dotted capital are
  folded one character for one before matching, so
  \texttt{at} counts characters of the text as written. A
  word boundary closes every template in the spaced locales,
  so an abbreviation's final point (\texttt{p.m.},
  \texttt{г.}) stays with the sentence.
  \texttt{time\_anchor(T)} and \texttt{@| timeline} share
  \texttt{period::anchor}: a span moves by calendar units
  keeping the anchor's grain (the month's last day where the
  target month lacks the day), except that an anchor finer
  than the day drops to the day when the offset names no unit
  finer than the day, a weekday offset and a time of
  day ask for a day or finer, a date with fields left out
  takes them from the anchor (under \texttt{forward}, the
  first such date at or after it). \texttt{timeline\_command}
  is row-aligned like \texttt{shift}: it evaluates the
  expression and the anchor per capsa, folds the point over
  the context (a change of anchor value starts a chain), and
  adds \texttt{when} and \texttt{from} to each record. A
  value that is not a \texttt{timex} record is carried as
  \texttt{\%(value; when; from)}.
\item \textbf{Unit libraries}: \texttt{units LIBRARY;} in a model
  imports a kaiv \texttt{.faiv} library (path relative to the model
  file; \texttt{use} merges) into the unit table the unital reading
  consults for every source the model mounts:
  \texttt{ModelAdapter::unit\_scale} answers from the imported
  definitions first (\texttt{kaiv::unit::scale\_with}), then the
  source's own. Loaded at construction, refused by \texttt{check}:
  an unreadable or malformed file, the same file twice, a name
  the table holds already (built in, or an earlier library).
  Unit names are letters in any script (the unital tokenizer
  admits Unicode letters), matched byte for byte as kaiv lists
  them; aliases read as their primary. A quantity prints its unit
  as written. Through kaiv-rs dev (0.15.0, path dependency) until
  kaiv publishes.
\item \textbf{The output locale} (\texttt{quarb::locale}) governs
  rendering only, never the value: a tool decides the locale in
  force by its layers, nearest first — \texttt{--locale},
  \texttt{QUARB\_LOCALE}, \texttt{\textasciitilde/.quarb/config.toml}
  (\texttt{[output] locale}), the system's \texttt{LC\_ALL} /
  \texttt{LANG} (\texttt{C} and \texttt{POSIX} canonical) — and
  renders what it prints through \texttt{OutputLocale}: numbers'
  decimal mark and grouping (CLDR's, with its minimum grouping
  digits), instants in the locale's medium date and time pattern
  through \texttt{strftime\_in}, \texttt{@| csv}'s delimiter (the
  semicolon where the decimal mark is the comma), and
  \texttt{sort}'s collation when the query names none
  (\texttt{set\_default\_collation}, read by
  \texttt{default\_text\_order}; text alone is collated, numbers
  and instants keep their own order). Digits are grouped only
  when asked (\texttt{--grouping}, \texttt{QUARB\_GROUPING=1},
  \texttt{[output] grouping = true}): a year is not
  \texttt{1,876}. The engine itself never renders under a locale.
  A command is a value, the same wherever the query runs, so
  \texttt{@| csv} and \texttt{@| table} inside a pipeline are
  canonical; when one \emph{closes} the query the tool renders
  it, as it renders \texttt{--csv} and \texttt{--table}:
  \texttt{Query::for\_rendering} runs the query with the
  closing command replaced by an internal stand-in that yields the
  rows, and the \texttt{Outcome} carries the command's columns and
  named delimiter (\texttt{ClosingTable}). \texttt{@| json}, \texttt{@| jsonl} and
  \texttt{@| kaiv} stay canonical. A reader
  (\texttt{number}, \texttt{tp}) takes its locale from its operand
  alone, and refuses a locale it has no table for. \texttt{qua --explain} reports the locale and its layer;
  the gates run with the environment's locale cleared. The session
  and wasm doors have no locale yet (the browser's
  \texttt{navigator.language} would be their system layer).
\item \textbf{Encoding} (\texttt{source::encode}): \texttt{@|
  encoding(LABEL)} is the output boundary and stands last. The
  engine has no byte value, so the tool takes the command off the
  end of the query, runs the rest and encodes what it would have
  printed (\texttt{qua}'s \texttt{OutSink}); met anywhere else it
  is refused by the executor. The command before it decides what a
  character the encoding cannot hold becomes: after \texttt{@|
  json} / \texttt{@| jsonl} the format's \texttt{\textbackslash
  u} escape (\texttt{source::Escape::Json}); after anything else
  the output is encoded while representable and refused at the
  first such character. Mail headers' RFC 2047 encoded words
  decode under their own charset through the same tables
  (\texttt{quarb-maildir}).
\end{itemize}

  \texttt{bibref(STANDARD)} (\texttt{quarb::bibref}) reads one
  reference text under a citation standard — \texttt{gost},
  \texttt{gb7714}, \texttt{cmos}, \texttt{ams}, an open tag set
  the command refuses outside of, naming it — into a record of
  the fields the grammar places without doubt (English names:
  \texttt{author}, \texttt{title}, \texttt{year},
  \texttt{journal}, \texttt{pages}, \ldots), its \texttt{genus}
  and the list \texttt{label}; a text that is no reference is
  null, as \texttt{strptime} answers for a text that is no date.
  Each grammar is a hand-written reader of the standard's
  punctuation (GOST's areas at \texttt{. –}, GB's type code after
  the title, Chicago's sentences and quoted titles, AMS's comma
  fields), the numbering prefix stripped first. The same module
  finds citations in prose (bracketed numbers and ranges with a
  pinpoint, author-year parentheses) and
  \texttt{TextModel::lower\_references} (quarb-text) applies both
  for the \texttt{?references=STANDARD} mount option: a paragraph
  or list item that parses becomes a \texttt{bib} node under the
  canonical campi (with the English aliases attached when no
  census is), its \texttt{::onym} the written number, the list
  ordinal, or party and year; the citations become \texttt{cit}
  nodes and the resolution pass runs again.

\section{Worked Example: the Filesystem Adapter}

\texttt{quarb-fs} implements the live trait over a directory tree. It
materializes the tree once, at construction, into arrays indexed by
\texttt{NodeId} (path, children, parent); the trait methods are then
trivial lookups:

\begin{lstlisting}[language=rust]
impl AstAdapter for FsAdapter {
    fn root(&self) -> NodeId { self.root }
    fn children(&self, node: NodeId) -> Vec<NodeId> { self.children[node].clone() }
    fn name(&self, node: NodeId) -> Option<String> {
        if node == self.root { return None; }   // "/" is unnamed
        self.paths[node].file_name().map(|n| n.to_string_lossy().into())
    }
    fn parent(&self, node: NodeId) -> Option<NodeId> { self.parents[node] }
}
\end{lstlisting}

\paragraph{Hidden entries and directory links \live.}
An entry whose name starts with a dot carries the
\texttt{<hidden>} trait (the mount root never does); such entries
are in the tree only under \texttt{-{}-hidden}. A symlink is a node
with a \texttt{target} crosslink, and a symlink to a directory of
the tree is also transparent to an explicit child step, as it is
in the file system: with \texttt{latest -> drafts},
\texttt{/latest/a.md} is the node \texttt{/drafts/a.md}, the same
one \texttt{/latest->*/a.md} reaches. The trait method behind this
is \texttt{child\_host(node)}, the node whose children a child step
reads; it defaults to the node itself, and the wrapping adapters
(mounts, grafts, models, reflection) forward it. The descendant
walk reads \texttt{children} alone, so \texttt{//} sees each file
once and a cycle of links cannot trap it. A broken link, and a
link whose target lies outside the mounted tree, stay leaves.

\paragraph{Ignore rules \live.}
The materializing walk uses \texttt{ignore::WalkBuilder}\,---\,the
same machinery ripgrep uses\,---\,so by default the adapter respects
\texttt{.gitignore}/\texttt{.ignore} files and skips hidden entries.
This came directly from running the skeleton: \texttt{qua '//*.rs'}
in the engine's own tree first returned a build artifact under
\texttt{target/}, because nothing yet excluded it. The adapter now
honors ignore rules by default, and \texttt{qua} exposes
\texttt{-{}-hidden} and \texttt{-{}-no-ignore} to opt back in. The
walk is currently eager (a targeted query still walks the whole
tree); a lazy traversal with cascading ignore rules is a planned
optimization. This is the pattern the guide follows: a concrete
problem, surfaced by running the code, drives the next slice.

\chapter{Building and Running}

\begin{lstlisting}[language=bash]
# from the engine workspace root
cargo build            # build the whole workspace
cargo test             # unit + integration + doc tests

# query a directory tree
cargo run -p qua -- '//*.rs' src/     # all Rust files under src/
cargo run -p qua -- '/README.md'      # a single top-level file

# query a document
cargo run -p qua -- '/users/0/name::' data.json
cargo run -p qua -- '//book[::pages > 200]:::id' catalog.xml
cargo run -p qua -- '//a::href' page.html
\end{lstlisting}

\noindent
\texttt{qua <QUERY> [PATH]} runs \texttt{QUERY} against the directory
\texttt{PATH} (default: the current directory) and prints each
matching path on its own line, so it composes in shell pipelines
alongside \texttt{sort}, \texttt{uniq}, and friends.


\chapter{Planned Integration Paths}

Beyond the direct \texttt{AstAdapter} implementation shown above,

\begin{itemize}
\item \textbf{Petgraph adapter.} A ready-made adapter over a
  \texttt{petgraph::Graph}, for Rust callers who transform their AST
  into a graph once and query it at speed. See
  \texttt{petgraph-adapter.md} in this project for the design note.
\item \textbf{Python bindings.} A \texttt{quarb} Python package
  exposing the engine and an \texttt{AstAdapter} base class.
\item \textbf{C FFI.} A C ABI for embedding the engine in other
  languages.
\end{itemize}

\noindent
Each will be added once the core language surface is substantial
enough to be worth binding.
